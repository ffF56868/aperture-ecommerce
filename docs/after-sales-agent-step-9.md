# 第九步：失败回滚与异常恢复

本步确保售后 Agent 遇到业务写入失败或工具持续异常时，不会留下“订单改了一半”或“不断重试”的脏状态。

## 1. 确认执行的事务回滚

用户点击“确认提交”后，取消订单、库存恢复、创建工单等实际写操作在数据库事务保存点中完成。

```text
用户确认
  -> 锁定确认申请
  -> 在事务保存点中取消订单或创建工单
       -> 成功：确认请求标记为已执行，写成功审计
       -> 业务错误：保存点回滚，确认请求标记为失败，写失败审计
       -> 未知异常：保存点回滚，返回安全提示，不泄露内部异常
```

例如创建退款工单时数据库异常，订单支付状态不会变化，工单不会被创建，确认申请会显示为“执行失败”。用户可以重新发起申请，管理员可在“工具执行审计”查看错误代码。

## 2. 连续工具失败自动转人工

系统会按“同一个工具”连续失败次数跟踪，而不是把不同工具的偶发失败混在一起。

当同一工具连续失败两次：

1. 停止本轮后续模型和工具调用，防止无意义重试与额外费用。
2. 创建或复用一张高优先级 `SYSTEM_EXCEPTION` 系统异常工单。
3. 将会话状态改为“已转人工”。
4. 在聊天页返回工单编号，告知用户等待人工处理。
5. 写入一条系统发起的审计记录，记录失败工具、次数和安全错误代码。

工单创建采用去重逻辑，同一会话的未关闭系统异常不会反复创建多张。

## 3. 对用户的表现

正常情况没有额外操作。如果系统无法连续完成核验，助手会明确提示已经转人工并给出工单号；不会假装查询成功，也不会暴露数据库、异常栈、配置或 API Key。

## 验收

- 模拟工单写入异常时：确认申请状态为失败，订单状态不变，失败审计存在。
- 模拟同一工具连续失败两次时：停止后续模型请求，创建高优先级系统异常工单，状态转人工。
