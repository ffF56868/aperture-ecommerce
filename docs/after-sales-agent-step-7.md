# 第七步：多 Agent 协作与专员权限隔离

本步将单一售后 Agent 拆分为一个总控和四个职责固定的专员。总控负责理解用户问题、协调工具调用并生成最终中文回复；专员只在自己的业务边界内工作。

## 协作角色

| 角色 | 可使用工具 | 不可做的事 |
| --- | --- | --- |
| 订单核验专员 | 查询本人订单、订单详情 | 查询其他用户订单、修改订单 |
| 售后规则专员 | 查询售后规则 | 执行退款、修改工单状态 |
| 工单进度专员 | 查询本人工单 | 查询或修改其他人工单 |
| 售后流程专员 | 创建确认申请、创建受控工单 | 直接退款、审核通过、修改支付状态 |

## 本轮执行流程

```text
用户消息
  -> 后端根据业务关键词生成协作计划
  -> 仅把本轮专员获准的工具交给总控模型
  -> 总控按需要协调订单核验、规则、工单或流程专员
  -> 每次工具执行写入实际执行专员、参数摘要和结果审计
  -> 保存本轮协作计划并返回用户可见回复
```

例如用户说“我想退款”：订单核验专员核验订单，售后规则专员核对条件，售后流程专员才可生成“确认提交”卡片。用户说“我的工单审核到哪了”：工单进度专员只读取该用户自己的工单状态。

## 安全边界

- 协作计划由后端的确定性路由生成，模型不能自行增加专员或工具。
- 未被本轮计划分配的专员工具不会出现在模型工具列表中；即使绕过模型直接请求，后端仍会以 `AGENT_ROLE_DENIED` 拒绝并记录审计。
- 所有既有的 JSON Schema、用户归属校验、确认卡、事务、幂等和工具白名单继续有效。
- Django 后台的“工具执行审计”中新增“执行 Agent”字段，可查看每次调用由哪个专员完成。

## 页面表现

售后助手右侧“售后处理”区会显示“本轮协作”，列出参与本次问题处理的专员。刷新页面或重新进入会话后，仍会读取最近一次保存的协作计划。
