# 第十步：危险工具调用安全闸门

本步完成售后 Agent 的最后一层运行时防护：即使模型受到错误指令或提示注入影响，尝试调用数据库、命令行、文件、网络、支付或直接审核类能力时，后端也会在任何业务函数执行前拦截。

## 拦截范围

安全闸门检查模型实际返回的函数名和参数结构，不扫描或误伤用户的普通售后描述。

会被直接阻断的函数能力包括：

- SQL、数据库查询或管理。
- Shell、PowerShell、终端、命令与子进程执行。
- 文件系统读取、写入、删除。
- 任意 HTTP、网页、Webhook、浏览器、`curl` 请求。
- 支付、转账、提现等资金操作。
- 未经确认的直接退款、取消订单、审核通过/拒绝、修改订单状态。

现有的订单查询、规则查询、工单查询、确认卡和受控建单工具均不受影响，仍需经过第七、八、九步的专员、权限、确认和事务检查。

## 执行流程

```text
模型提出函数调用
  -> 危险函数名检查
       -> 命中：拒绝、脱敏审计、停止本轮工具循环
  -> 已注册工具白名单检查
       -> 不在白名单：拒绝、审计
  -> 危险参数结构检查
       -> 命中 sql / command / file / url / token 等参数：拒绝、仅记录字段名
  -> 专员角色、权限等级、待确认状态、JSON Schema、用户归属校验
  -> 受控业务工具执行
```

危险调用的模型循环会被立即终止，不会把拒绝结果回传给模型继续尝试其他系统能力，也不会进入“连续工具失败自动建单”的普通异常流程。

## 审计与隐私

后台“工具执行审计”会保存：工具名、拦截错误代码、执行时间和危险参数字段名。不会保存 SQL 文本、命令正文、URL、Token、密码或其他敏感参数值。

用户只会收到中文安全提示：“我只能处理当前账号的售后事项，已拦截不属于售后范围的系统操作请求。”

## 验收覆盖

- `run_sql` 等危险函数名被标记为 `DANGEROUS_TOOL_CALL_BLOCKED`，不会执行也不会记录 SQL 正文。
- 普通但未注册的函数继续以 `TOOL_NOT_ALLOWED` 拒绝。
- 已注册工具携带 `endpoint`、`command`、`token` 等危险额外参数时，以 `DANGEROUS_ARGUMENT_BLOCKED` 拒绝，参数值不进入审计。
- 模型尝试危险函数时，只有一次模型请求，后续工具循环立即停止。
